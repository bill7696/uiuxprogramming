# 시세 알림

관심 종목이 목표 가격에 닿으면 바로 알려드립니다.

BTC·ETH·SOXL처럼 코인과 주식을 함께 지켜보는 사람이 목표 가격에 닿은 종목을
바로 알 수 있게 하는 서비스입니다.

## 사용자 경험 계획

| 항목 | 내용 |
| --- | --- |
| 사용자 | BTC·ETH·SOXL처럼 코인과 주식을 함께 지켜보는 사람 |
| 목적 | 목표 가격에 닿은 종목을 바로 안다 |
| 핵심 행동 | 관심 종목과 목표 가격을 등록하고 이메일 알림을 신청한다 |
| 정보 순서 | 소개 → 주요 기능 → 이용 방법 → 알림 설정 → 알림 받기 |

## 화면 구조

```
body
├── header        h1 · p · nav (a ×5)
├── main
│   ├── section#about      h2 · h3 · p · img
│   ├── section#features   h2 · div.tabs > button.tab ×3 · div.panel ×3 (h3 · p)
│   ├── section#steps      h2 · ol > li
│   ├── section#settings   h2 · div.event-grid > article.event-card ×3
│   │                        (테마 button · 종목 input + p 글자 수 · 동의 checkbox + p + button)
│   └── section#subscribe  h2 · form (label · input · button) · p.form-message
└── footer        p
```

## 파일

| 파일 | 역할 |

| `style.css` | 페이지 전체의 색·크기·여백·배치와 반응형 규칙 |
| `assets/images/service.jpg` | 관심 종목 화면 이미지 |
| `script.js` | 알림 신청 폼 검증, 테마·글자 수·동의 상태 변경, 기능 탭 전환 |

글꼴은 Spoqa Han Sans Neo 웹폰트를 CDN으로 불러와 씁니다 (`index.html`의 `<link>`).
불러오지 못하면 Apple SD Gothic Neo · Malgun Gothic 순으로 대체됩니다.

## 2주차 구조 변경 기록

**서비스 이름을 "코인 알림"에서 "시세 알림"으로 바꿈**
처음에는 코인만 다루려 했으나 지켜볼 종목에 SOXL이 들어갔습니다. SOXL은 코인이 아니라
반도체 ETF여서, 이름에 "코인"이 남아 있으면 주식은 담을 수 없는 서비스로 읽힙니다.
이름이 다루는 범위를 좁게 말하지 않도록 바꿨습니다.

**제목과 목록을 네 개의 `<section>`으로 나누고 id를 붙임**
처음에는 `<main>` 안에 제목과 목록을 평평하게 늘어놓았습니다. 이 상태에서는 메뉴를 붙여도
링크가 도착할 지점이 없었습니다. 정보 순서에 적은 네 덩어리를 그대로 영역으로 끊고
`about`·`features`·`steps`·`subscribe` id를 붙여 메뉴와 연결했습니다.

**메뉴 이름을 도착 영역의 제목과 같은 말로 맞춤**
메뉴를 먼저 쓰고 제목을 나중에 쓰다 보니 두 이름이 서로 달랐습니다. 누른 메뉴와 도착한
자리의 제목이 다르면 제대로 이동했는지 확인이 안 되어, 네 쌍을 같은 말로 통일했습니다.

**버튼 문구를 "확인"에서 "시세 알림 신청하기"로 바꿈**
1주차 버튼 문구는 "확인"이었습니다. 무엇이 확인되는지 알 수 없어, 누른 뒤에 일어날 일을
문구가 그대로 말하도록 고쳤습니다.

**1주차 index.html에 있던 `style.css`·`script.js` 연결을 뺌**
2주차는 정보 구조와 이동 흐름을 완성하는 단계라 화면 모양을 입히지 않습니다.
또 1주차 스크립트는 지금은 없는 버튼을 찾는 코드여서 연결해 두면 오류가 납니다.
두 파일은 1주차 결과물이라 저장소에는 그대로 둡니다.

## 3주차 CSS 변경 기록

**`index.html`에 `style.css`를 다시 연결했습니다.**
2주차에는 정보 구조와 이동 흐름만 완성하느라 연결을 빼 두었습니다. 3주차부터 이 파일이
페이지 전체의 시각적 표현을 담당합니다.

**`.feature-list`에 `display: flex`와 `gap: 20px`, 자식 카드에 `flex: 1`을 적용했습니다.**
세 기능이 세로로 늘어서 있던 것이 같은 너비의 카드 세 개로 한 줄에 놓였습니다.
같은 종류의 정보라는 것이 한눈에 보이고, 기능끼리 나란히 비교할 수 있습니다.

**`.content-section`에 `padding`·`border`·`border-radius`·흰 배경을 주었습니다.**
네 영역의 경계가 없어 어디까지가 한 덩어리인지 알기 어려웠는데, 각 영역이 카드로 끊겼습니다.
사용자가 지금 보고 있는 정보가 어디서 시작해 어디서 끝나는지 구분합니다.

**`h1`·`h2`·`h3`의 `font-size`를 44px·30px·20px로 벌렸습니다.**
제목과 본문이 비슷한 크기라 읽는 순서가 없었는데, 무엇을 먼저 봐야 할지 드러납니다.
페이지를 훑으면서 필요한 영역으로 바로 건너뛸 수 있습니다.

**입력창과 버튼에 `hover`·`focus-visible`·`active`와 `transition`을 넣었습니다.**
마우스를 올리면 색이 바뀌고, Tab으로 이동하면 포커스 링이 보이고, 누르면 버튼이 1px 내려갑니다.
마우스로 눌렀을 때는 링이 나오지 않습니다. 키보드로 다니는 사람에게는 현재 위치를 보여주고,
마우스로 쓰는 사람에게는 불필요한 테두리를 남기지 않기 위해 `:focus` 대신 `:focus-visible`을
썼습니다.

## 4주차 반응형 변경 기록

**`.feature-list`를 `display: flex`에서 `display: grid`로 바꾸고
`grid-template-columns: repeat(auto-fit, minmax(260px, 1fr))`를 적용했습니다.**
카드가 260px보다 좁아지지 않는 선에서 열 수가 자동으로 바뀝니다. 1100px에서는 3열,
769px에서는 2열, 768px 이하에서는 1열이 됩니다. 화면이 줄어도 카드 안의 글이 찌그러지지
않아, 어떤 기기에서 열어도 기능을 같은 방식으로 훑을 수 있습니다.

**`header`·`main`·`footer`에 `width: 100%`를, 이미지에 `width: 100%`와
`max-width: 360px`를 주었습니다.**
고정 폭이던 콘텐츠 축과 이미지가 화면 너비를 따라 줄어듭니다. 좁은 화면에서 옆으로 잘리거나
가로 스크롤이 생기지 않습니다.

**`@media (max-width: 768px)`에서 메뉴·소개·폼의 배치를 세로로 바꿨습니다.**
가로로 늘어서 있던 메뉴 네 개, 글과 이미지, 입력창과 버튼이 위아래로 쌓입니다.
손가락으로 누를 수 있게 버튼에 `min-height: 48px`을 주고 입력창과 버튼을 화면 너비에
맞췄습니다. 작은 화면에서 눌러야 할 것이 서로 붙어 잘못 눌리는 일이 줄어듭니다.

**같은 조건에서 글자와 세로 여백을 줄였습니다.**
h1을 44px에서 36px로, h2를 30px에서 28px로, 섹션 안쪽 여백을 40px에서 24px로 줄였습니다.
좁은 화면에서 제목이 여러 줄로 꺾이지 않고, 한 화면에 들어오는 내용이 늘어납니다.

## 5주차 기능 추가 기록

**`index.html`의 `</body>` 바로 위에서 `script.js`를 불러오고 폼에 `novalidate`를 붙였습니다.**
화면 요소가 먼저 만들어진 뒤에 스크립트가 실행되어야 버튼과 문구를 찾을 수 있습니다.
`type="email"` 입력창은 브라우저가 먼저 검사해 자기 말풍선을 띄우고 제출을 막습니다.
그러면 우리가 준비한 안내 문구가 나올 기회가 없어, 검사를 브라우저 대신 스크립트가 맡도록
`novalidate`를 주었습니다.

**폼·입력창·버튼·결과 문구 네 요소에 id를 붙이고 `querySelector`로 찾습니다.**
`#subscribe-form` · `#email` · `#subscribeButton` · `#subscribeMessage` 네 개를 스크립트 맨 위에서
한 번씩 찾아 변수에 담아 둡니다.

**폼 `submit` 이벤트에 `handleSubscribe` 함수를 연결했습니다.**
버튼을 누르거나 입력창에서 Enter를 치면 같은 함수가 실행됩니다. `event.preventDefault()`로
페이지가 새로 고쳐지는 기본 동작을 막고, 입력값을 `trim()`으로 다듬어 변수에 담습니다.

**입력값에 따라 세 갈래로 다른 안내 문구를 보여줍니다.**

| 입력값 | 안내 문구 | 표시 |
| --- | --- | --- |
| 비어 있음 | 이메일을 입력해 주세요. | 붉은 글자·배경 · 입력창 붉은 테두리 |
| `@`와 `.`이 없는 형식 | 이메일 형식이 올바르지 않습니다. … | 붉은 글자·배경 · 입력창 붉은 테두리 |
| 올바른 형식 | (입력한 주소) 으로 시세 알림을 보내드립니다. | 초록 글자·배경 · 버튼 "신청 완료" |

형식은 정규식 `/^[^\s@]+@[^\s@]+\.[^\s@]+$/`로 확인합니다. 오류일 때는 입력창으로 포커스를
돌려보내 바로 고칠 수 있게 했습니다.

**처리 결과에 따라 문구의 스타일과 버튼 상태가 바뀝니다.**
`showMessage` 함수가 `#subscribeMessage`에 `is-error`·`is-success` 클래스를, 입력창에 `is-invalid`
클래스를 붙였다 뗍니다. 두 클래스는 글자색과 배경색을 함께 바꿉니다. 신청이 끝나면 버튼 문구를 "신청 완료"로 바꾸고 `disabled`로 잠가
초록색으로 보입니다. 문구가 비어 있을 때는 `:empty`로 숨겨 자리를 차지하지 않습니다.

**`isSubscribed` 상태 변수로 입력창을 다시 고칠 때의 동작을 나눴습니다.**
신청이 끝난 뒤 이메일을 고치면 버튼을 원래 문구로 되돌리고 잠금을 풀어 다시 신청할 수 있습니다.
신청 전이라면 오류 표시만 지웁니다. 같은 `input` 이벤트라도 상태에 따라 다르게 반응합니다.

## 6주차 이벤트 처리와 동적 UI 기록

**주요 기능 카드 세 장을 탭 UI로 바꿨습니다.**
4주차의 `.feature-list` 격자를 `.tabs`(버튼 3개)와 `.panel`(패널 3개)로 바꿨습니다. 버튼의
`data-target`이 패널의 id를 가리키고, `aria-controls`·`aria-selected`·`aria-labelledby`·`hidden`으로
어느 탭이 선택됐는지 보조기기에도 알립니다. `querySelectorAll('.tab')`로 버튼을 모두 찾아
`forEach`로 같은 `handleTabClick`을 연결하고, 누른 버튼은 `event.currentTarget`으로 알아냅니다.
`resetTabsAndPanels`가 전부 초기화한 뒤 `activateTab`이 누른 탭과 패널만 켭니다.

**알림 설정 영역을 추가하고 click · input · change 이벤트를 하나씩 연결했습니다.**

| 이벤트 | 요소 | 함수 | 바뀌는 것 |
| --- | --- | --- | --- |
| click | `#themeButton` | `handleThemeClick` | `body.dark` 토글(`classList.toggle`) · 버튼 문구 · `aria-pressed` |
| input | `#ticker` | `handleTickerInput` | `#tickerCount`에 `value.length + " / 10"` (`maxlength="10"`) |
| change | `#agreeCheck` | `handleAgreeChange` | `#agreeMessage` 문구와 `is-ready` 클래스 · `#startButton`의 `disabled` |

**비활성 버튼과 완료 버튼의 색을 분리했습니다.**
5주차에는 `:disabled`가 곧 "신청 완료"라 초록이었습니다. 6주차의 알림 시작 버튼은 동의 전에
비활성으로 시작하므로, `:disabled`는 회색으로 두고 신청이 끝난 버튼에만 `is-done` 클래스를
붙여 초록으로 보이게 했습니다.

**다크 테마는 JavaScript가 클래스만 바꾸고 색은 CSS가 맡습니다.**
`body.dark` 아래에 바탕·카드·탭·패널·입력창·안내 문구의 색을 따로 적었습니다.

**768px 이하에서는 탭을 세로로 쌓고 설정 카드를 한 열로 놓습니다.**
선택된 탭은 밑줄 대신 왼쪽 세로선으로 표시하고, 버튼은 폭 100%에 높이 48px 이상으로 둡니다.
